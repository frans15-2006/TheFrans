## 2026-05-22 - Optimizing high-frequency DOM updates and animation cycles
**Learning:** In vanilla JS applications with dynamic lists (like a shopping cart), using `innerHTML +=` in a loop causes the browser to re-parse and re-render the entire container for every iteration, leading to O(n²) performance degradation. Similarly, high-frequency UI updates like price counters can trigger multiple overlapping `requestAnimationFrame` cycles, causing visual jank and wasted CPU cycles.
**Action:** Always batch DOM updates by building a full HTML string first or using a `DocumentFragment`. For animations triggered by user actions, always store the RAF ID and use `cancelAnimationFrame` to ensure only one cycle is active at a time. Cache frequently accessed DOM elements at the top level to avoid redundant lookups.
