## 2025-05-15 - [Compositor-Thread Optimization for Interactive Elements]
**Learning:** Animations using `left`, `top`, or `width` trigger the browser's Layout and Paint stages, which are executed on the main thread and can cause frame drops if the main thread is busy. Using compositor-only properties like `transform: translate3d()` and `transform: scaleX()` allows the GPU to handle the animation, keeping the main thread free for other tasks. Additionally, caching layout-dependent values (like `scrollHeight`) outside of high-frequency events (like `scroll` or `mousemove`) prevents "forced synchronous layouts" (layout thrashing).
**Action:** Always prefer `transform` and `opacity` for animations. Use `will-change: transform` for elements that animate frequently. Cache dimensions and distances using `resize` listeners rather than querying them in `scroll` or `mousemove` handlers.
