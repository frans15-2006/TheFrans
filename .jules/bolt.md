## 2025-05-23 - Eliminating Layout Thrashing in High-Frequency UI Updates
**Learning:** High-frequency events (scroll, mousemove) in the original codebase were triggering layout thrashing by repeatedly calling `getBoundingClientRect()` and updating layout-inducing properties like `width`, `left`, and `top`. Moving these updates to compositor-only properties (`transform`) and caching layout measurements (like bounding rects) on less frequent events (like `mouseenter`) significantly reduces the workload on the main thread and improves frame consistency.
**Action:** Always prefer `transform: translate3d()` and `scale()` for high-frequency positioning and sizing. Cache layout measurements in entry/exit events (mouseenter/mouseleave) rather than reading them on every frame of a high-frequency interaction.
